## What we've been doing this session — Frontend v4 design

### The screen review — best of each

Five Stitch screens were reviewed. No single screen was the answer, but each owned something:

| Screen | What it did best |
|---|---|
| **The Manuscript** | Visual identity — the cream palette, serif headline with italic emphasis, editorial breathing room. It had *personality*. You knew what kind of tool this was before reading a word. |
| **Soft Light Refined** | Structure — the clearest layout bones: left nav strip, centre content, right rules panel. The most legible column hierarchy. |
| **Deep Ink** | Content components — tag pills (ENTRY POINT, INVERSION OF CONTROL), "Why this matters" callout boxes, rules panel with ID badges. It showed what the actual content language of Compass should look like. |
| **Minimalist Flow** | Nothing to borrow — generic layout, placeholder copy, no personality. |
| **Soft Light Edition** | Superseded by Soft Light Refined. |

**The synthesis:** The Manuscript's *feeling*, Soft Light Refined's *structure*, Deep Ink's *content components*. None of them alone. That combination became the v4 brief.

|---|---|

| UI font | Public Sans |
| Code font | JetBrains Mono |
| Accent | Sage emerald `#4A7862` |
| Background | Warm cream `#FDFCFB` |
| Outer shell | `#F0EFED` with max-width 1440px |

### Layout — v4 direction
Four fixed columns inside a max-width shell:

```
[ Nav strip 52px ] [ Section list 216px ] [ Detail 1fr ] [ Rules 280px ]
```

- **Nav strip** — icon + label buttons: What, Start, Stable, Hot, Rules, Config. Active state emerald. Completion tick on visited items.
- **Section list** — user context card at top (name, repo, day), then section headers and item cards
- **Detail panel** — serif typography, breadcrumbs, tag chips, paragraph → rule hover linking
- **Rules panel** — contextually filtered rule cards matching the active file

### Topbar
Three product modes centred, absolute-positioned:

```
[ Compass wordmark ]     [ Onboarding | Workspace | Community ]     [ settings · avatar ]
```

- **Onboarding** — structured walkthrough of an unfamiliar codebase (current view)
- **Workspace** — personal working environment, notes, saved items
- **Community** — team directory, org chart, colleague onboarding, Slack invites

### Chat workspace
Collapsible horizontal drawer pinned to the bottom. Expands upward to ~46vh. All four columns remain visible above it at all times — **unified space, no breaks**.

Expanded state: two-panel — conversation thread (left) + live code/output (right).

### Key interaction: paragraph → rule linking
Hovering a paragraph in the detail panel highlights the corresponding rule card in the rules panel and scrolls it into view. Implemented via `data-rule` attributes + JS mouseenter/mouseleave.

## Design principles guiding all decisions

1. **Unified space** — no modals, overlays, or breaks from the four-column grid. The brain stays oriented.
2. **Content first** — serif typography, generous whitespace, structured hierarchy. Feels like reading documentation, not using a dev tool.
3. **Rules are always present** — the rules panel is contextual but always visible. The connection between content and rules is made explicit (hover linking).
4. **Chat is a tool, not a chatbot** — it lives at the bottom as a workspace, not a floating bubble.
5. **User context in the workspace, not the topbar** — the topbar carries product navigation; who you are and what you're working on lives in the section list.
